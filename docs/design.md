# My Company: 디자인 방향 (T-031)

> 상태: CEO 결정(D-018)으로 **후보 A 확정**. 토큰 값의 원본은 `src/renderer/src/assets/tokens.css`이며 이 문서는 원칙과 이유만 유지한다. 아래 팔레트 hex는 초안 값이고 구현 값은 tokens.css를 따른다.
> 확정 사항: 다크와 라이트 테마 둘 다 제공(시스템 설정을 따르고 수동 전환 가능). 제목/라벨은 한글 픽셀 폰트 Galmuri11, 본문은 Pretendard. 이미지 에셋은 아직 반입하지 않고 CSS만 쓴다.
> 폰트 라이선스는 2026-11-12에 공식 저장소에서 직접 확인했다 (SIL OFL 1.1). 출처와 URL은 `docs/assets-licenses.md`.

## 1. 현재 상태와 문제

- `base.css`는 electron-vite 템플릿의 `--ev-c-*` 변수를 그대로 쓴다. 제품 토큰이 아니다.
- `onboarding.css`는 색을 hex로 직접 박았다 (`#7bd88f`, `#f0b429`, `#ff8a80`, `#3b6fd4`, `#8ab4ff`, `#111`). 간격(6/8/12/16/24px), 폰트 크기(13~24px), 반경(4/8/12px)도 값이 제각각이다.
- 컴포넌트가 없다. `.wizard button`, `.card`, `.badge`가 온보딩 전용 선택자(`.wizard` 하위)에 묶여 있어 다른 화면에서 재사용할 수 없다.
- 폰트는 Inter와 시스템 폰트 나열이다. 한글 전용 지정이 없고 번들 폰트도 없어 OS마다 모양이 다르다.
- 앱 셸이 없다. `main { padding: 24px }` 안에 위저드 하나가 있다. 가상 사무실, 티켓 보드, 결정 인박스가 들어갈 틀이 없다.
- 결과적으로 "회색 박스 + 회색 글씨"의 기본 웹 폼 느낌이고, 게더타운 같은 세계관이 전혀 없다.

## 2. 디자인 방향 후보

공통 원칙(세 후보 모두): 토큰은 CSS 변수 한 파일, 패널은 "테두리 2px + 단색 그림자(블러 없음)"로 픽셀 감성을 낸다. 상태는 색만으로 전달하지 않고 아이콘/텍스트를 함께 쓴다. 본문 대비 4.5:1 이상.

### 후보 A. 아늑한 픽셀 오피스 (다크 웜톤) -- 추천

- 분위기: 해 질 녘 아늑한 사무실. 어두운 나무/보라빛 갈색 바탕에 따뜻한 크림색 글씨, 포인트는 노랑/민트. 게더타운의 따뜻한 느낌에 가깝다. 맵은 밝은 바닥 타일이라 UI 패널이 어두우면 맵이 돋보인다.
- 팔레트(토큰, hex):
  - `--bg-app` #1f1a2b / `--bg-panel` #2a2438 / `--bg-panel-raised` #352e47 / `--bg-inset` #17131f
  - `--border` #4a4161 / `--border-strong` #6b5f8a
  - `--text` #f4ecd8 / `--text-muted` #b8aecb (panel 위 대비 약 7:1, 구현 시 재측정) / `--text-faint` #8b81a1 (장식 전용, 본문 금지)
  - `--accent` #ffc857 (주 버튼, 선택) / `--accent-ink` #2a1f00 (accent 위 글씨) / `--accent-2` #6ee7b7 (민트, 작업 중)
  - `--ok` #7bd88f / `--warn` #f0b429 / `--bad` #ff8a80 / `--info` #8ab4ff
  - 부서 색(맵 구역, 배지): `--dept-exec` #c792ea, `--dept-rnd` #6fb7ff, `--dept-fin` #ffb86b, `--dept-plan` #7be0b0
- 폰트: 본문 Pretendard (알려진 바 SIL OFL 1.1, 한글 지원, 가변 폰트). 제목/라벨 강조는 둥근모꼴 또는 Galmuri11 같은 한글 픽셀 폰트 (알려진 바 둘 다 OFL. 둘 중 하나만 선택). 코드는 시스템 monospace. 픽셀 폰트는 제목과 짧은 라벨에만 쓴다. 긴 본문에 쓰면 가독성이 떨어진다.
- 크기 스케일: 12/14/16/20/28. 간격은 4px 배수 (4/8/12/16/24/32). 반경은 거의 쓰지 않는다 (0 또는 4px, 모서리를 깎은 픽셀 느낌은 `clip-path`/border-image로 선택 적용).
- 컴포넌트 원칙:
  - 패널: `--bg-panel` + 2px `--border` + 4px 오프셋 단색 그림자(`4px 4px 0 #0e0b14`). 제목 줄은 `--bg-panel-raised`.
  - 버튼: 기본은 panel-raised 바탕 + 2px 테두리, 주 버튼은 `--accent` 바탕. 눌림 시 그림자 제거하고 2px 이동. 포커스 링은 3px `--info`, 오프셋 2px.
  - 입력: `--bg-inset` 바탕, 2px `--border`, 포커스 시 `--accent` 테두리 + 포커스 링.
  - 배지: 작은 사각형(반경 2px), 점 아이콘 + 글씨. 상태별 `--ok/--warn/--bad/--info`를 배경 15% 투명 + 글씨 원색으로.
- 앱 셸: 상단 상태바 40px (회사 이름, 제공자별 사용량 게이지, 결재함 배지) / 좌측 맵 영역(가변, PixiJS 캔버스 자리, 최소 600px) / 우측 패널 360px(탭: 직원 로그, 티켓, 결재함, 접기 가능). 폭 900px 미만이면 우측 패널이 하단 시트로 내려간다. 온보딩은 셸 없이 중앙 카드 레이아웃(셸의 패널 컴포넌트 재사용).
- 장점: 미션(게더타운풍)과 가장 잘 맞음. 맵 에셋(Kenney 등 밝은 타일)과 대비가 좋음. 장시간 보는 운영 도구로 눈이 편함.
- 단점: 픽셀 폰트/그림자 표현 때문에 일부 CSS 기교가 필요. 과하면 유치해 보일 수 있어 절제가 필요.
- 구현 난이도: 중. 토큰과 컴포넌트 CSS만으로 가능, 이미지 에셋 의존 낮음.

### 후보 B. 다크 사이버 오피스 (채택 안 함)

네이비/블랙 바탕에 네온 시안/마젠타 포인트. 구현은 쉽지만 게더타운의 아늑함이 없어 미션과 어긋나고 개성이 약해 채택하지 않았다.

### 후보 C. 밝은 파스텔 픽셀 오피스 (채택 안 함, 라이트 테마로 일부 흡수)

크림/파스텔 톤. 단독 방향으로는 채택하지 않았다. CEO가 다크와 라이트 둘 다를 요청해, 후보 C의 따뜻한 크림 톤은 A의 라이트 테마로 반영했다.

### 비교 요약

| 항목                         | A 아늑 픽셀 다크 | B 사이버 다크 | C 파스텔 라이트 |
| ---------------------------- | ---------------- | ------------- | --------------- |
| 게더타운 부합                | 높음             | 낮음          | 높음            |
| 장시간 가독성                | 높음             | 중            | 중              |

## 3. 에셋 방침 (맵 타일, 아바타, 아이콘)

| 방식                                                                            | 장점                                                | 단점                                                                                     | 라이선스/리스크                                                                                                          |
| ------------------------------------------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Kenney 에셋 팩 (예: Roguelike Indoors, Tiny Town 계열, UI Pack Pixel Adventure) | 무료, 즉시 사용, 타일/가구/캐릭터 풍부, 스타일 일관 | 다른 앱과 겹치는 인상, 직원별 개성 표현 한계, 팩마다 타일 크기(16px 등)가 달라 혼합 곤란 | 알려진 바 Kenney 에셋은 CC0 (출처 표기 불필요). 단, 이번에 공식 페이지에서 직접 확인하지 못했다. 사용할 팩별로 확인 필요 |
| 다른 CC0 소스 (OpenGameArt, itch.io 일부)                                       | 선택지가 많음                                       | 팩별로 라이선스가 다름 (CC-BY, CC-BY-SA, GPL 혼재). 확인 비용이 큼                       | 라이선스를 항목별로 확인하기 전에는 사용 금지                                                                            |
| 직접 제작 (픽셀 아트, 디자이너 또는 AI 보조)                                    | 완전한 일관성, 브랜드화, 권리 명확                  | 시간과 비용이 큼. 우리 팀에는 아트 직원이 없다                                           | 직접 만든 것은 문제없음. AI 생성 이미지는 권리/정책 확인 필요 (CEO 판단 사안)                                            |

방침(제안):

1. MVP는 CC0 팩(Kenney 우선) + 단색/CSS 위주 UI. UI 크롬(패널, 버튼, 배지)은 에셋 없이 CSS로만 만든다. 이것이 후보 A의 구현 난이도를 "중"으로 유지하는 핵심이다.
2. 맵 타일/아바타는 T-020에서 팩 하나를 골라 통일한다. 타일 크기는 하나로 고정한다 (16 또는 32px, 정수 배율 확대, `image-rendering: pixelated`).
3. 에셋마다 출처 URL, 라이선스 문구, 확인 날짜를 `docs/assets-licenses.md`에 기록한다. 기록이 없는 에셋은 머지하지 않는다 (reviewer-qa 체크 항목).
4. 직접 제작은 브랜드 정체성이 필요해지는 시점(공개 전 등)에 재검토한다.

## 4. 추천: 후보 A

이유:

- 미션이 "게더타운처럼 보며 운영"이다. A는 그 세계관에 맞고 B는 맞지 않는다.
- C와 달리 라이트 테마를 만들지 않아 T-031 범위에 맞고, 로그/코드/결재함을 오래 보는 운영 화면에 눈이 편하다.
- UI 크롬을 CSS만으로 만들 수 있어 에셋 라이선스 리스크와 작업량이 작다.
- 토큰을 한 파일에 두므로 CEO가 나중에 색감을 바꿔도 비용이 작다.

## 5. 기존 스타일에서 바꿀 점 (ui-dev 구현 가이드)

1. `assets/tokens.css` 신규: 위 팔레트, 간격(`--space-1..6` = 4..32px), 폰트 크기(`--fs-*`), 반경, 테두리, 그림자, 포커스 링 변수 정의. `base.css`의 `--ev-c-*` 제거.
2. 색 hex 직접 사용 제거: `#7bd88f` 등 모두 토큰으로 치환. 린트 또는 grep 검사로 `onboarding.css`와 `components.css`에 hex가 남지 않게 한다 (tokens.css 제외).
3. `.wizard` 하위에 묶인 `button`, `.card`, `.badge`, `input`, `.notice`, `.hint`를 `components.css`로 분리하여 `.btn`, `.btn--primary`, `.panel`, `.badge--*`, `.input` 같은 공용 클래스로 만든다. `.wizard button` 전역 요소 선택자는 없앤다.
4. 폰트 번들: Pretendard(가변 woff2 서브셋)와 선택한 픽셀 폰트를 `src/renderer/src/assets/fonts/`에 포함 (`@font-face`, `font-display: swap`). 라이선스 파일 동봉. 외부 CDN 로드 금지 (`.claude/rules/ipc-security.md`의 원격 코드 로드 금지 취지).
5. `main { padding: 24px }` 제거하고 앱 셸 컴포넌트(`AppShell`: 상태바, 맵 영역 슬롯, 우측 패널 슬롯)로 교체. 온보딩은 셸 바깥의 중앙 카드 레이아웃.
6. 온보딩 2단계의 긴 카드는 AI별 탭(키보드 화살표 이동, `role="tablist"`)으로 분리. 완료/경고 상태는 배지로 요약.
7. 접근성: 포커스 링 토큰 통일, 버튼 최소 높이 36px, 상태는 색 + 아이콘/텍스트, `prefers-reduced-motion`에서 애니메이션 끔. 대비는 구현 후 실제 측정한다 (위 수치는 추정).
8. 반응형: 390px에서 한 열, 1280px에서 맵 + 우측 패널. 두 폭 스크린샷이 완료 조건이다.

## 6. CEO 결정 (D-018, 2026-11-12)

1. 방향: 후보 A 확정. 다크와 라이트 테마를 모두 만든다.
2. 에셋: 이미지/스프라이트 반입은 보류(CC0 팩 방침 미정). UI는 CSS만 쓴다.
3. 폰트: 제목/라벨 Galmuri11, 본문 Pretendard. 마음에 안 들면 되돌린다(토큰 `--font-pixel` 한 줄로 교체 가능).

## 7. 리스크

- 폰트 라이선스는 확인 완료(`docs/assets-licenses.md`). 이미지 에셋은 반입 전에 항목별 확인이 필요하다.
- 픽셀 스타일 과용 시 유치해 보일 수 있다. 크롬은 절제하고 맵에서 개성을 낸다.
- 대비는 `assets/tokens.test.ts`가 두 테마 모두 WCAG AA로 검사한다.
- 폰트 번들로 앱 용량이 늘어난다 (구현 후 폰트 4종 약 2.2MB, 서브셋 미적용).
