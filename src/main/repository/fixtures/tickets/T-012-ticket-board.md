# T-012: 티켓 보드 UI

- **상태:** backlog
- **담당:** ui-dev
- **부서:** 개발팀
- **브랜치:** feature/T-012
- **의존:** T-004, T-005

## 목표
backlog / in-progress / done 칸반 보드를 만든다.

## 완료 조건
- [ ] 티켓 카드에 번호, 제목, 담당, 부서가 보인다
- [ ] 상태 변경이 마크다운 파일 이동으로 반영된다 (IPC 경유)
- [ ] 필터(부서, 담당)가 있다
- [ ] 로딩/빈/오류 상태가 처리된다

## 메모
- 작성: pm·cto (MVP 계획, `company/decisions/done/D-001-initial-decisions.md` 참고)
- 제품 모델 정정(CEO 확정: 회사 1개, 프로젝트 N개): 보드는 회사 전체 티켓이 기본이다. 프로젝트 필터와 배지는 T-042, 티켓 생성·편집은 T-044가 맡으므로 이 티켓에서는 하지 않는다. **기본 조직 반영(CEO 확정: 기본 직원은 cto, cfo, hr):** 새 회사에는 pm·developer가 없고 담당이 비거나 존재하지 않는 티켓이 정상이다. 카드에서 "담당 없음"과 "담당 직원 없음(채용 필요)"을 오류가 아닌 상태 배지로 표시하고, 담당 필터에 "담당 없음"을 포함한다. 프로젝트 소속 티켓의 PM 필요 안내(실행 대기 표시)는 T-042가 맡는다. 필터 구조는 프로젝트 필터를 나중에 끼울 수 있게 부서·담당 필터와 같은 방식으로 둔다.
