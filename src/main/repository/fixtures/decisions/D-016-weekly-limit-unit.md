# D-016: 주간 한도의 단위 (달러 vs 구독 사용률)

- **관련 티켓:** T-009 (후속: T-019)
- **작성일:** 2026-11-12
- **상태:** pending (T-034에서 추천안 A로 임시 진행)

## 질문
초기 결정(D-001)은 "Claude Pro 주간 한도의 50%"처럼 **구독 한도 기준**이었는데, 구독에는 달러 금액이 없습니다. T-009는 임시로 **달러 예산** 단일 단위(`usd`)로 구현했습니다(`WeeklyLimitUnit`으로 확장 여지를 둠). 어떤 단위로 한도를 관리할까요?

## 선택지
1. **A. 달러 예산 (임시안)** — 제공자별 주간 달러 상한. CLI 출력의 비용(`total_cost_usd`)과 직접 비교할 수 있다. 구독 요금제 사용자는 실제 과금이 아니라 가상의 기준값이 된다.
2. **B. 구독 사용률(%)** — 구독 한도 대비 %. 사용자 의도와 가깝지만, 구독 한도의 실제 값을 앱이 알 수 없고 CLI가 알려주는 방식도 확인되지 않았다.
3. **C. 요청 수/토큰 수** — CLI가 보고하는 사용량 수치 기준. 정확하지만 비개발자에게 직관적이지 않다.

## 추천안과 이유
- 추천: A로 시작, 이후 CLI가 제공하는 사용량 정보를 확인한 뒤 B/C를 `WeeklyLimitUnit`에 추가
- 이유: 현재 앱이 확실히 읽을 수 있는 수치는 비용(USD)과 토큰 수치뿐이다. 구독 한도 값은 알 수 없다.

## 영향
- A 선택 시: 현재 구현 유지. T-019(CFO 사용량·주간 한도)는 비용 합계와 비교.
- B/C 선택 시: 계약(`WeeklyLimit`), 검증, 온보딩 문구, T-019 설계가 바뀐다.
- 결정이 늦어지면: 임시안 A로 T-019 전까지 진행 (T-019 시작 전에는 확정 필요).
