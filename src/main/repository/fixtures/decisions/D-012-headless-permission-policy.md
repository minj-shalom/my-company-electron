# D-012: 헤드리스 실행 권한 정책

- **관련 티켓:** T-007 (후속: T-016, T-017)
- **작성일:** 2026-11-12
- **상태:** done

## 질문
앱이 `claude -p`로 직원/COO 틱을 실행할 때, 허용되지 않은 도구 호출은 승인할 방법이 없어 실패하거나 멈춥니다. 어떤 권한 정책으로 실행할까요? 지금은 권한 옵션을 전혀 주지 않아 권한이 필요한 도구는 거부됩니다.

## 선택지
1. **A. `--allowedTools` 허용 목록만** — 최소 권한. 직원/작업별로 허용 도구를 명시. 가장 안전하다.
2. **B. `--permission-mode acceptEdits` + 허용 목록** — 파일 편집은 자동 승인하고 나머지는 목록으로 제한. 편의성은 높지만 편집 범위가 넓어진다.
3. **C. 모든 권한 우회 (비권장)** — 사용자 컴퓨터에서 승인 없이 임의 명령을 실행할 수 있어 위험하다. 이 앱의 보안 규칙(IPC/CLI 실행 제한)과 맞지 않는다.

## 추천안과 이유
- 추천: A (필요하면 B를 직원별로 제한적으로)
- 이유: 최소 권한 원칙. 허용 목록은 회사 폴더의 설정 파일에서 읽고, renderer 입력으로는 받지 않는다. 자유 문자열 `extraArgs`는 인자 주입 위험이라 열거형/허용 목록 타입으로만 받는다.

## 영향
- A 선택 시: 구현 티켓에서 `buildArgs`에 타입 안전하게 추가. 도구 거부 시 T-017의 권한 카드(사람 승인)로 연결.
- B 선택 시: 편집 자동 승인 범위를 정해야 한다.
- 결정이 늦어지면: 현재처럼 권한이 필요한 도구가 거부됨. T-016(COO 틱 러너), T-017이 이 결정 없이는 실질 동작이 제한된다.

## 결정 (사람이 작성)
- 선택: A (`--allowedTools` 허용 목록만)
- 메모: 2026-11-12 CEO 확정. 세부는 모두 추천대로: 실행별 임시 설정 사용(영구 파일 아님), hr은 전용 실행, Codex/Gemini처럼 경로 제한이 없는 제공자는 제안만 하는 경로, hr 쓰기 허용 4항목(직원 파일, org.md, archive, project.md의 직원/PM 줄) 승인(project.md는 줄 diff 검증의 한계 인정). 민감 변경은 CEO 직접 지시여도 카드를 유지(추천대로).
